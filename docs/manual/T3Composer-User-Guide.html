T³Composer 사용자 가이드 T³Composer User Guide

AI No-code React + Spring 자연어 · 설계서 · 기존 화면을 입력으로 받아 운영 가능한 화면(JSX + Java + SP + 메뉴 SQL)을 한 번에 생성·수정하는 AI 도구입니다. 본 가이드는 설치부터 7개 메뉴 사용까지 한눈에 안내합니다. An AI tool that generates and modifies production-ready screens (JSX + Java + SP + menu SQL) from natural language, design documents, or existing screens. This guide covers installation through usage of all 7 menus at a glance.

💡 첫 기동 시간💡 First-time startup

최초 docker compose up 은 backend 의 Maven 의존성 다운로드 (수백 MB) 때문에 5~10분 걸릴 수 있습니다. 이후 기동은 30초 내. backend 가 healthy 상태가 되면 frontend 도 자동 작동합니다. The first docker compose up may take 5–10 minutes due to backend Maven dependency download (several hundred MB). Subsequent starts take under 30 seconds. Once backend is healthy, frontend works automatically.

⚠️ 포트 충돌⚠️ Port conflicts

5173 · 8090 · 11433 · 14433 중 이미 사용 중인 포트가 있으면 기동 실패. docker-compose.yml 의 해당 서비스 ports: 매핑을 변경하거나 기존 프로세스를 종료하세요. lsof -i :5173 또는 netstat -ano | findstr 5173 (Windows) 로 확인 가능. Startup fails if any of 5173 · 8090 · 11433 · 14433 are in use. Change the ports: mapping in docker-compose.yml or stop the conflicting process. Check with lsof -i :5173 or netstat -ano | findstr 5173 (Windows).

Insight LLM (선택)Insight LLM (optional)

Insight LLM 은 자연어 질의·온톨로지 답변용 별도 서비스로 호스트 포트 9160 에 직접 기동해야 합니다. 미기동 시 Insight 기능만 비활성 (UI 에 'upstream error' 표시) 되고, T3Composer 의 화면 생성 기능은 정상 동작합니다. Insight LLM is a separate service for natural-language queries and ontology answers, running directly on host port 9160. Without it, only the Insight feature is disabled (UI shows 'upstream error'); T3Composer's screen generation still works normally.

  • 설치 안내: 별도 insight-llm 저장소 참조 (사내 위키 또는 관리자 문의) Setup: refer to the separate insight-llm repository (internal wiki or contact admin)
  • 대안: 기본 Composer 흐름은 Anthropic API 만으로 충분 — Insight 는 자연어 SQL 질의·온톨로지 답변 같은 부가 기능 Alternative: the basic Composer flow runs fine with just the Anthropic API — Insight is for add-on features like NL SQL queries and ontology answers

Target System 연결 (선택)Target System Connection (optional)

운영 wingui DB (T3SmartSCM) 의 메뉴 트리·LangPack·소스 코드를 실시간으로 참조하려면 Target DB 연결이 필요합니다. 연결 없이도 docker 내장 target-mssql 컨테이너로 기본 동작합니다. To reference the production wingui DB (T3SmartSCM) menu tree, LangPack, and source code in real time, a Target DB connection is required. Without it, the bundled target-mssql container provides basic functionality.

  1. .env 에 운영 DB 정보 입력: Add production DB info to .env: 
    TARGET_T3SERIES_DB_URL=jdbc:sqlserver://<host>:1433;database=T3SMARTSCM;encrypt=true;trustServerCertificate=true
TARGET_T3SERIES_DB_USERNAME=sa
TARGET_T3SERIES_DB_PASSWORD=<password>
TARGET_T3SERIES_DB_DRIVER_CLASS=com.microsoft.sqlserver.jdbc.SQLServerDriver
  2. backend 컨테이너 재기동: docker compose up -d --force-recreate composer-backend Restart backend container: docker compose up -d --force-recreate composer-backend
  3. UI 의 상단 Target Selector → [💾 Storage] → [연결 테스트] 로 검증 Verify via UI top Target Selector → [💾 Storage] → [Test connection]
대안: UI 에서 직접 입력Alternative: enter directly in UI

일회성이면 UI 의 Target Selector dropdown → 💾 Storage 버튼 → JDBC URL/계정 입력 후 [연결 테스트] 로 즉시 설정. 입력값은 composer-db 에 영구 저장됩니다 (단, .env 의 TARGET_*_DB_* 가 채워져 있으면 매 startup 마다 덮어쓰므로 영구 설정은 .env 사용). For one-off changes, use the Target Selector dropdown → 💾 Storage button → enter JDBC URL/credentials → [Test connection]. The values persist in composer-db (but if TARGET_*_DB_* in .env is set, it overwrites at every startup — use .env for permanent config).

자연어 생성 (Natural Lang.) Natural Language Generation

가장 자유로운 방식입니다. 만들고 싶은 화면을 한국어 문장으로 적으면 Claude 가 화면 패턴·데이터 바인딩·SP·메뉴 SQL 까지 한꺼번에 생성합니다. The most flexible mode. Write your screen requirements as natural-language sentences, and Claude generates the pattern, data binding, SP, and menu SQL together.

흐름Flow

  1. 모드 선택 → "자연어 생성" 클릭 In mode selection, click "Natural Language"
  2. 큰 textarea 에 요구사항 작성 (예: "사용자별 부서/직위 관리 화면을 만들어 줘. 검색조건은 부서·사용자명, 그리드에 코드·이름·이메일") Type requirements in the large textarea (e.g., "Create a user-by-department/position management screen. Filters: department, user name. Grid: code, name, email.")
  3. 선택사항 — 아래 4가지 중 하나 또는 여러 개 사용 가능: Optional — choose one or several of these:
    • SCM UI Mockup 선택 — 운영 화면 mockup 1개를 참조 템플릿으로 (mockup ↔ UI Pattern 상호 배타) Pick SCM UI Mockup — one production mockup as reference (mockup ↔ UI Pattern are mutually exclusive)
    • UI Pattern 선택 — T3MES 패턴 1개를 참조 마크업으로 Pick UI Pattern — one T3MES pattern as reference markup
    • 참조 파일 첨부 — SQL · 설계서 이미지 · 캡처 (최대 5개, 파일당 5MB · 텍스트는 prompt inline · 이미지는 Anthropic vision) Attach reference files — SQL, design images, screenshots (up to 5, 5MB each · text inlined into prompt · images use Anthropic vision)
    • Data Source 선택 — DB Entity (별자리 맵에서 테이블/SP 선택) · Ontology Q&A · 인라인 쿼리 Pick Data Source — DB Entity (pick table/SP from constellation map) · Ontology Q&A · inline query
  4. [화면 생성 시작] 클릭 → Composer 작업공간이 열리며 Claude 가 ===FILE: 마커로 산출물 6~8종 출력 Click [Start Generation] → Composer workspace opens; Claude emits 6–8 artifacts marked with ===FILE:
  5. 우측 [실행 화면 LIVE] 탭에서 자동으로 화면 미리보기 확인 The right [Screen LIVE] tab automatically shows the preview
  6. 오류 시 자동보완 ON 으로 두면 Claude 가 자체적으로 1회 수정 시도 With "auto-fix on error" ON, Claude attempts one self-fix automatically

"TB_AD_USER" 처럼 실제 테이블명을 prompt 에 적으면 Composer 가 자동으로 운영 DB 의 컬럼을 조회해 프롬프트에 주입합니다 (Target DB 가 연결돼 있어야 함). Data Source 별자리 맵에서 직접 선택하면 더 강한 강제력 — Claude 가 이름이 비슷한 다른 테이블로 임의 대체하지 않습니다. If you write a real table name like "TB_AD_USER" in the prompt, Composer auto-queries production DB columns and injects them into the prompt (Target DB must be connected). Picking from the Data Source constellation map enforces this more strongly — Claude won't substitute with a similarly-named table.

V2 distinction

MENU_CD 에 _V2 접미어를 붙여도 zAxios URL · Controller · Service · Entity · Table · SP 등 백엔드 자원은 원본과 공유합니다 (단일 자원 공유 기본). v 접미어는 메뉴 코드 한정. 기존 화면 수정 (Modify Existing) Modify Existing

운영 화면을 그대로 두고 일부만 변경할 때. For changing only parts of a production screen while leaving the rest intact.

  • 자연어 수정 (NL Modify) — 현재 화면 소스를 Claude 에 제공하고 대화로 수정 요청. 가장 빠르고 직관적. 작은 변경 (필드 추가/이동, 라벨 변경, 검색조건 추가 등) 에 적합. NL Modify — provide current source to Claude and request changes via chat. Fastest and most intuitive. Best for small changes (add/move fields, label changes, new filters).
  • 단계별 수정 (Step Modify) — 기존 화면을 spec 으로 분해해 수정할 부분만 변경. 구조적 큰 변경 (layer 추가, 마스터-디테일 분리 등) 에 적합. Step Modify — decompose existing screen into a spec, change only target parts. Best for structural changes (add a layer, split master-detail).

두 방식 모두 EXISTING_MODIFY 모드로 진입하며, 진입 시 원본 메뉴를 선택하면 그 화면의 모든 소스 (JSX, Java 4종, SP) 를 세션 아티팩트로 import 합니다. 사용자가 요청한 변경분만 새 버전으로 생성되고, 미변경 파일은 baseline 유지. Both enter EXISTING_MODIFY mode. When you select the source menu, all its sources (JSX, 4 Java files, SP) are imported as session artifacts. Only the parts you ask to change get a new version; unchanged files keep the baseline.

⚠️ 키 보안⚠️ Key security

키는 backend DB 에 암호화되어 저장됩니다. 로그/스냅샷에는 prefix(12자) + suffix(4자) + SHA-256 prefix(8자) 만 노출. 키 전체는 다시 표시되지 않으므로 별도 안전한 곳에 백업. The key is stored encrypted in the backend DB. Logs and snapshots only show prefix (12 chars) + suffix (4 chars) + SHA-256 prefix (8 chars). The full key is never re-displayed, so back it up elsewhere.
