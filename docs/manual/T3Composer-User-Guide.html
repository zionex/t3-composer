T³Composer 사용자 가이드

AI No-code React + Spring 자연어 · 설계서 · 기존 화면을 입력으로 받아 운영 가능한 화면(JSX + Java + SP + 메뉴 SQL) 을 한 번에 생성·수정하는 AI 도구입니다. 본 가이드는 설치부터 7개 메뉴 사용까지 한눈에 안내합니다.

💡 첫 기동 시간

최초 docker compose up 은 backend 의 Maven 의존성 다운로드 (수백 MB) 때문에 5~10분 걸릴 수 있습니다. 이후 기동은 30초 내. backend 가 healthy 상태가 되면 frontend 도 자동 작동합니다.

⚠️ 포트 충돌

5173 · 8090 · 11433 · 14433 중 이미 사용 중인 포트가 있으면 기동 실패. docker-compose.yml 의 해당 서비스 ports: 매핑을 변경하거나, 기존 프로세스를 종료하세요. lsof -i :5173 또는 netstat -ano | findstr 5173 (Windows) 로 확인 가능.

0-3. Insight LLM (선택)

Insight LLM 은 자연어 질의·온톨로지 답변용 별도 서비스로 호스트 포트 9160 에 직접 기동해야 합니다. 미기동 시 Insight 기능만 비활성 (UI 에 'upstream error' 표시) 되고, T3Composer 의 화면 생성 기능은 정상 동작합니다.

  • 설치 안내: 별도 insight-llm 저장소 참조 (사내 위키 또는 관리자 문의)
  • 대안: 기본 Composer 흐름은 Anthropic API 만으로 충분 — Insight 는 자연어 SQL 질의·온톨로지 답변 같은 부가 기능

0-4. Target System 연결 (선택)

운영 wingui DB (T3SmartSCM) 의 메뉴 트리·LangPack·소스 코드를 실시간으로 참조하려면 Target DB 연결이 필요합니다. 연결 없이도 docker 내장 target-mssql 컨테이너로 기본 동작합니다.

  1. .env 에 운영 DB 정보 입력: 
    TARGET_T3SERIES_DB_URL=jdbc:sqlserver://<host>:1433;database=T3SMARTSCM;encrypt=true;trustServerCertificate=true
TARGET_T3SERIES_DB_USERNAME=sa
TARGET_T3SERIES_DB_PASSWORD=<password>
TARGET_T3SERIES_DB_DRIVER_CLASS=com.microsoft.sqlserver.jdbc.SQLServerDriver
  2. backend 컨테이너 재기동: docker compose up -d --force-recreate composer-backend
  3. UI 의 상단 Target Selector → [💾 Storage] → [연결 테스트] 로 검증
대안: UI 에서 직접 입력

일회성이면 UI 의 Target Selector dropdown → 💾 Storage 버튼 → JDBC URL/계정 입력 후 [연결 테스트] 로 즉시 설정. 입력값은 composer-db 에 영구 저장됩니다 (단, .env 의 TARGET_*_DB_* 가 채워져 있으면 매 startup 마다 덮어쓰므로 영구 설정은 .env 사용).

상단 막대 — Target System / API 키 상태

모드 선택 화면 상단에는 현재 활성 Target System (예: T3SERIES) 과 API 키 등록 상태 (녹색=등록됨 · 주황=미등록) 가 표시됩니다. API 키가 미등록이면 화면 생성 시 오류 — 우측 아이콘 클릭 또는 §9-2 참조.

2-1. 자연어 생성 (Natural Lang.)

가장 자유로운 방식입니다. 만들고 싶은 화면을 한국어 문장으로 적으면 Claude 가 화면 패턴·데이터 바인딩·SP·메뉴 SQL 까지 한꺼번에 생성합니다.

흐름

  1. 모드 선택 → "자연어 생성" 클릭
  2. 큰 textarea 에 요구사항 작성 (예: "사용자별 부서/직위 관리 화면을 만들어 줘. 검색조건은 부서·사용자명, 그리드에 코드·이름·이메일")
  3. 선택사항 — 아래 4가지 중 하나 또는 여러 개 사용 가능:
    • SCM UI Mockup 선택 — 운영 화면 mockup 1개를 참조 템플릿으로 (mockup ↔ UI Pattern 상호 배타)
    • UI Pattern 선택 — T3MES 패턴 1개를 참조 마크업으로
    • 참조 파일 첨부 — SQL · 설계서 이미지 · 캡처 (최대 5개, 파일당 5MB · 텍스트는 prompt inline · 이미지는 Anthropic vision)
    • Data Source 선택 — DB Entity (별자리 맵에서 테이블/SP 선택) · Ontology Q&A · 인라인 쿼리
  4. [화면 생성 시작] 클릭 → Composer 작업공간이 열리며 Claude 가 ===FILE: 마커로 산출물 6~8종 출력
  5. 우측 [실행 화면 LIVE] 탭에서 자동으로 화면 미리보기 확인
  6. 오류 시 자동보완 ON 으로 두면 Claude 가 자체적으로 1회 수정 시도

2-3. 기존 화면 복사 (Copy Existing)

이미 운영 중인 화면을 복사해서 새 메뉴로 만들 때 사용. Composer 가 원본 JSX·Java·SP 를 통째로 가져와 세션 아티팩트로 import 한 뒤, 사용자가 자연어로 변경분만 요청합니다.

  1. "기존 화면 복사" 클릭
  2. 운영 메뉴 트리에서 복사할 원본 메뉴 선택
  3. 신규 메뉴 코드/경로 입력 (예: UI_AD_USER_MGMT_V2)
  4. SourceBundle 분석 패널에서 원본의 SP / URL / Entity 확인
  5. "AI 자동 분석" ON (기본) → 4-step Wizard 에 spec 자동 prefill
  6. Wizard 진행 + 변경 요청 → 새 산출물 생성
V2 distinction

MENU_CD 에 _V2 접미어를 붙여도 zAxios URL · Controller · Service · Entity · Table · SP 등 백엔드 자원은 원본과 공유합니다 (단일 자원 공유 기본). v 접미어는 메뉴 코드 한정.

2-4. 기존 화면 수정 (Modify Existing)

운영 화면을 그대로 두고 일부만 변경할 때.

  • 자연어 수정 (NL Modify) — 현재 화면 소스를 Claude 에 제공하고 대화로 수정 요청. 가장 빠르고 직관적. 작은 변경 (필드 추가/이동, 라벨 변경, 검색조건 추가 등) 에 적합.
  • 단계별 수정 (Step Modify) — 기존 화면을 spec 으로 분해해 수정할 부분만 변경. 구조적 큰 변경 (layer 추가, 마스터-디테일 분리 등) 에 적합.

두 방식 모두 EXISTING_MODIFY 모드로 진입하며, 진입 시 원본 메뉴를 선택하면 그 화면의 모든 소스 (JSX, Java 4종, SP) 를 세션 아티팩트로 import 합니다. 사용자가 요청한 변경분만 새 버전으로 생성되고, 미변경 파일은 baseline 유지.

3History — 작업 이력

이전에 진행한 모든 Composer 세션을 조회·이어하기 할 수 있습니다.

  • 상태별 필터: ACTIVE (진행 중) · COMPLETED (메뉴등록+적용 완료) · ARCHIVED (보관)
  • 각 세션 카드에는 — 모드 · 제목 · 마지막 메시지 · Target · 생성일 · 산출물 카운트가 표시됨
  • [이어하기] 클릭 → Composer 의 ComposerWorkspace 가 해당 세션으로 열림 (메시지 기록·산출물 그대로 복원)
  • [보관] 클릭 → ARCHIVED 로 전환 (영구 삭제 아님 — 필요 시 ACTIVE 로 되돌릴 수 있음)
자동 COMPLETED 전이

세션이 ① 메뉴 등록 (MENU_SQL 적용) AND ② 아티팩트 적용 (JSX/Java/SP 중 1개 이상) 이 모두 완료되면 서버가 자동으로 COMPLETED 로 전이합니다. 수동으로 ACTIVE 로 되돌리면 다시 수정 가능.

4SCM UI Mockup — 갤러리

T3SmartSCM 의 54개 운영 화면 mockup 을 카테고리 별로 모은 갤러리입니다. Composer 의 "단계별 생성" 에서 출발점 템플릿으로 사용.

  • 5개 카테고리 — Core (12) · Domain (13) · Dashboard (16) · ControlBoard (4) · Meta (9)
  • productLine 필터 — T3SmartSCM · PlaNEL · 전체
  • 검색바 — 코드 · 라벨 · 설명 · 메뉴 ID · 메뉴명 · 경로 전체 텍스트 검색
  • 매핑 메뉴 보기 — 각 mockup 카드의 [사용 메뉴 N개] 클릭 → 해당 mockup 을 사용하는 운영 메뉴 263개 매핑 테이블 펼침
  • 브라우저 뒤로가기 — Mockup 안에서 한 단계씩 이동 (다른 탭으로 빠지지 않음)

5UI Pattern — T3MES 패턴 카탈로그

T3MES 퍼블리싱 산출물 29개 HTML 파일에서 분리한 730개 TabPage 패턴 카탈로그.

  • 트리 구조 — Section (SCM/MES) → Group → File → TabPage
  • iframe 미리보기 — TabPage 클릭 → 우측에 원본 HTML 그대로 렌더 (auto-activate 부트스트랩 주입돼 선택한 패널만 활성)
  • Composer 연동 — UI Pattern Picker Dialog 로도 호출 가능 (자연어 생성·단계별 생성에서 참조)
분리본 재생성

원본 frontend/public/t3mes/*.html 가 변경되면 node scripts/split-t3mes-tabs.cjs 재실행 → full/ (iframe 용) + lite/ (AI 참조 용) + _data/t3mes-tabs.json 일괄 재생성.

7Ontology — 비즈니스 의미 사전

SCM 도메인의 비즈니스 의미를 4개 영역으로 정리한 사전. 자연어 질의·Composer 의 데이터 바인딩 추론에 사용.

영역역할
Q&A"실적과 계획을 비교하고 싶다" 같은 자연어 → SP/SQL 변환 사전
Entity비즈니스 엔티티 (Demand · Supply · Inventory · Plan 등) 와 그 속성·관계
View화면 의도 (월별 수요계획 입력 · 시뮬레이션 비교 · 재고 현황 등) 사전
ProcessS&OP 프로세스 단계 (Demand Planning · Capacity Check · Approval 등)
상태 (status) 와 신뢰도

각 항목은 DRAFT (초안) · CONFIRMED (확정) · MERGED (병합) · DEPRECATED (폐기) 상태를 가집니다. Composer 와 자연어 질의 시 자동으로 CONFIRMED 만 사용 — DRAFT 는 사용자가 확인해 승격해야 적용됩니다.

8Dashboard — 위젯 빌더

위젯 기반 사용자 대시보드 — 미리 정의된 위젯 (KPI · Chart · Grid) 을 react-grid-layout 위에 배치해 자신만의 대시보드를 구성합니다.

  • 위젯 카탈로그 — Gallery 의 Grid/Chart/KPI 사전이 위젯 후보
  • 편집 모드 — 드래그·리사이즈로 12-col grid 위에 배치
  • 뷰어 모드 — 편집 영역 숨기고 데이터만 실시간 표시 (Viewer Mode Toggle)
  • 저장 — 사용자별로 영구 저장, 다음 접속 시 자동 복원
Insight LLM 연동 (선택)

Insight LLM 이 호스트 port 9160 에 기동돼 있으면 위젯 데이터를 자연어 질의로 동적 조회 가능 (예: "최근 3개월 매출 추이 보여줘"). 미기동 시 사전 정의 위젯만 사용 가능.

9부록

9-1. Target System 전환

여러 운영 시스템 (T3SERIES · PLANNEL · LGES_NEXTSCM 등) 을 다룬다면 상단 Target Selector dropdown 으로 전환. 선택한 Target 에 따라:

  • 운영 DB 가 자동 라우팅 (메뉴 트리·LangPack·소스 코드 조회)
  • 적용되는 룰·hook 이 달라짐 (T3SERIES = wingui-core · MSSQL · ChartJs / PLANNEL = AG-Grid · PostgreSQL 등)
  • 산출물의 패키지·import·코딩 컨벤션이 Target 에 맞춰 생성됨

설정은 localStorage 에 저장되어 다음 접속 시에도 유지됩니다.

9-2. API 키 등록

상단 우측의 색상 뱃지 (녹색 = 등록됨 · 주황 = 미등록) 클릭 → API Key Dialog.

  1. console.anthropic.com 에서 키 발급
  2. Dialog 의 입력란에 키 (sk-ant-...) 붙여넣기 — 80자 이상 필수 (짧으면 거부)
  3. [저장] → 자동 검증 후 뱃지가 녹색으로 변경
⚠️ 키 보안

키는 backend DB 에 암호화되어 저장됩니다. 로그/스냅샷에는 prefix(12자) + suffix(4자) + SHA-256 prefix(8자) 만 노출. 키 전체는 다시 표시되지 않으므로 별도 안전한 곳에 백업.

9-3. 첨부 파일 — 타입별 처리 방식

파일 타입처리비고
텍스트 (.sql/.json/.md/.txt/.csv ...)prompt 본문에 inline (파일당 12K자 cap)코드 펜스로 감싸 Claude 에 전달
이미지 (.png/.jpg/.gif/.svg ...)Anthropic multimodal vision blocks설계서 / 캡처 / 와이어프레임 / mockup 모두 지원

크기/개수 제한: 최대 5개 · 파일당 5MB. 초과 시 화면에 안내 메시지.

일반 팁

  • 오류 시 자동보완 체크박스 ON 으로 두면 화면 실행 오류 시 Claude 가 1회 자동 수정
  • 화면 자동 실행 — JSX 산출물이 추가되면 우측 [실행 화면 LIVE] 가 자동으로 미리보기. 수동 [화면 실행] 불필요
  • 아티팩트 소스 보기 — 좌측 트리에서 파일 클릭 → 우측 [아티팩트 소스] 탭에 코드 표시
  • 변경 후 sync — Composer 산출물을 wingui 본 환경에 적용하려면 별도 sync 스크립트 (관리자 전용)
  • 긴 작업 세션 — Composer 는 자동 세션 저장 — 브라우저 닫아도 History 에서 이어하기 가능
자주 묻는 질문
  • Q. 생성된 화면이 wingui sync 후 동작 안 함
    → preview runtime 의 graceful-degradation mock 으로 화면 실행은 통과했지만 wingui 본 환경 컴파일 실패. 룰/hook 이 잡지 못한 케이스 → 관리자에게 문의.
  • Q. AI 추천 카드가 0개
    → 자연어가 너무 짧거나 키워드가 카탈로그와 안 맞음. 더 구체적 문장으로 재시도 또는 mockup picker 사용.
  • Q. Target DB 미연결 — 메뉴 트리에 'source: local' 표시
    → §0-4 절차로 Target DB 연결 또는 docker 내장 target-mssql 의 기본 데이터로 작업 가능.
  • Q. 인터넷 차단된 사내망 — 매뉴얼 어떻게 봐요?
    → 본 HTML 은 외부 CDN/웹폰트 의존성 0. 더블클릭으로 오프라인 열람 가능.
