# 분석 기준 vs 조건

둘 다 "컬럼을 고르는 것"처럼 보여서 헷갈릴 수 있는데, 역할이 다릅니다.

---

## 분석 기준 — "무엇별로 볼까?"

데이터를 **어떻게 나눠서 볼지** 정하는 축입니다. 차트의 X축, 그룹핑 기준, 테이블의 분류 기준이 됩니다.

> **예시** — 생산 수량을 보고 싶을 때, 분석 기준에 따라:
> - 품목별 생산 수량
> - 공장별 생산 수량
> - 월별 생산 수량
> - 고객별 주문 수량

---

## 조건 — "무엇만 볼까?"

데이터를 **어디까지 조회할지** 제한하는 필터입니다. SQL의 `WHERE`에 가까운 개념입니다.

> **예시**
> - 최근 3개월 데이터만
> - 특정 공장만
> - 특정 품목 그룹만
> - 완료 상태만
> - 삭제되지 않은 데이터만

---

## 비교 요약

| 구분 | 질문 | SQL 관점 | 화면 관점 |
|------|------|----------|-----------|
| **분석 기준** | 무엇별로 볼까? | `GROUP BY` | X축, 범주, 행/열 기준 |
| **조건** | 무엇만 볼까? | `WHERE` | 필터, 조회 범위 |

---

## 예시

| 항목 | 값 |
|------|----|
| 지표 | 주문 수량 |
| 분석 기준 | 고객 |
| 조건 | 최근 3개월, 국내 고객 |

→ 결과: **최근 3개월 국내 고객별 주문 수량**

여기서 `고객별`이 분석 기준이고, `최근 3개월` / `국내 고객`이 조건입니다.

---

## UX 개선 방향

지금 UI에서는 둘 다 후보 컬럼 리스트처럼 보여 구분이 약합니다.

- **조건 탭**: `기간 조건 / 상태 조건 / 조직 조건 / 품목 조건`처럼 **필터 성격**으로 묶기
- **분석 기준**: `시간 기준 / 품목 기준 / 고객 기준 / 조직 기준`처럼 **그룹핑 축**으로 묶기

---

## Step 3 우측 패널 개선 방향

조건 단계의 우측 패널은 단순히 선택한 조건 목록만 보여주면 안 됩니다.  
사용자가 이 단계에서 확인해야 하는 것은 **"조건을 적용하면 결국 어떤 위젯이 만들어지는가"** 입니다.

### 우측 패널 표시 순서

1. 만들어질 위젯 문장
2. 시각화 유형
3. 측정값
4. 분석 기준
5. 조회 조건

조건은 최종 문장의 앞부분에 붙고, 분석 기준은 `~별`, 측정값은 문장의 핵심 지표로 표현합니다.

### 위젯 문장 생성 규칙

| 상황 | 예시 문장 |
|------|-----------|
| 조건 + 분석 기준 있음 | `Agenda 식별자, 파일 스토리지 식별자 조건으로 회의체별 참석자 수` |
| 조건 없음 | `전체 데이터 기준으로 회의체별 참석자 수` |
| KPI형 (분석 기준 없음) | `전체 기준 참석자 수` |

> **결론**: Step 3 우측 패널은 `조건 요약`이 아니라 **`위젯 요약`** 이어야 합니다.  
> 조건 목록은 별도 `조회 조건` 섹션으로 내려가고, 선택된 조건이 없으면 `전체 데이터 기준`으로 표시합니다.
